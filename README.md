# NFL Player Trajectory Prediction

**Chenwei (Felix) Wan · NFL Big Data Bowl 2026**

A player-trajectory inference pipeline using engineered motion and player-interaction features, a two-layer GRU with attention pooling, and an ensemble of five trained fold models.

## Task

Given observed player tracking data and the competition-provided context, predict future player positions `(x, y)` for the requested frames. This is a sports trajectory forecasting project, rather than a trading strategy.

## Pipeline

`Tracking data → feature engineering → last 10 observed frames → per-fold scaling → GRU → attention pooling → displacement increments → ensemble average → bounded coordinates`

- Motion features: position, speed, direction, velocity components, lags, rolling statistics and exponential moving averages.
- Interaction features: opponent proximity, local density, receiver/defender relationships and distance-weighted summaries of nearby players.
- Route patterns: a saved scaler and K-means classifier label recent movement patterns.
- Geometric features: estimated endpoints, direction alignment and ball-landing context.
- Model: two-layer GRU with 128 hidden units, four-head attention pooling and a feed-forward output head.
- Output: cumulative displacement over a maximum horizon of 94 frames, averaged across five models and clipped to field boundaries.

The original saved notebook log reported **174 input features** and successful loading of all five models. This is an artifact-loading record, not a performance measurement.

## Reproduction

The code expects a Kaggle competition environment with `kaggle_evaluation.nfl_inference_server`, the NFL Big Data Bowl 2026 prediction dataset and these trusted model artifacts in `Config.MODEL_DIR`:

- `route_kmeans.pkl`, `route_scaler.pkl`
- `model_fold1.pt` through `model_fold5.pt`
- `scaler_fold1.pkl` through `scaler_fold5.pkl`

1. Add the competition input dataset and the model-artifact dataset to a Kaggle notebook.
2. Set `Config.MODEL_DIR` to the artifact dataset directory (currently `/kaggle/input/enhanced-gru-inference-v1/`).
3. Match dependency versions to the original training environment; version information is not supplied here.
4. Run the notebook. Outside the competition rerun, it calls `run_local_gateway`; inside the competition rerun, it calls `serve`.

The competition data, weights, scaler objects and training code are **not included** in this repository. Installing `requirements.txt` alone is insufficient to reproduce predictions. Only load pickle/weight files from a trusted source.

## Review notes

Before extending or retraining this implementation:

- Check acceleration components against the direction convention: velocity uses `sin` for x and `cos` for y, while acceleration currently swaps them.
- Enforce a stored feature schema: missing columns are currently filtered out and training/inference column order is not explicitly asserted.
- Verify prediction row order against the test template; output is currently generated by player grouping and sorted frame IDs.
- Wrap route turning-angle differences across the ±π boundary.
- Review short-history, missing-player and sparse-neighbor cases.

These are review findings, not reported improvements. Changes to feature semantics should be evaluated against the training pipeline and may require retraining.
